# 🔁 Migration Notes — MySQL → PostgreSQL / Supabase

Tài liệu chuyển đổi thiết kế database MySQL sang PostgreSQL/Supabase.

> ⚠️ Phase này **chỉ tạo file SQL mới** — chưa migrate dữ liệu, chưa đổi backend.
> File MySQL gốc giữ nguyên: `database/yang_homestay_schema.sql` + `yang_homestay_seed.sql`.
> Database cũ `hotel_management` **không bị đụng tới**.

---

## 1. Bảng 24 — giữ nguyên domain model

Toàn bộ 24 bảng của lược đồ MySQL được chuyển nguyên vẹn (tên, cột, quan hệ, dữ liệu seed):
PROPERTY → UNIT → AVAILABILITY → BOOKING. Không thêm/bớt bảng.

## 2. Map kiểu dữ liệu

| MySQL | PostgreSQL | Ghi chú |
|---|---|---|
| `INT AUTO_INCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | Seed dùng ID tường minh → `BY DEFAULT` (không phải `ALWAYS`) |
| `INT UNSIGNED` | `BIGINT` + `CHECK (col >= 0)` | PG không có unsigned |
| `TINYINT(1)` | `BOOLEAN` | `TRUE` / `FALSE` |
| `ENUM('a','b',...)` | `TEXT` + `CHECK (col IN ('a','b',...))` | Linh hoạt hơn, dễ mở rộng |
| `TINYINT UNSIGNED` (rating, weight, day_of_week) | `SMALLINT` + `CHECK` | VD: `CHECK (rating BETWEEN 1 AND 5)` |
| `TIMESTAMP DEFAULT CURRENT_TIMESTAMP` | `TIMESTAMPTZ NOT NULL DEFAULT now()` | |
| `TIMESTAMP ... ON UPDATE CURRENT_TIMESTAMP` | `TIMESTAMPTZ` + trigger `set_updated_at()` | Trigger trong `005_functions.sql` |
| `JSON` | `JSONB` | audit_logs |
| `DECIMAL(10,7)` | `NUMERIC(10,7)` | lat/lng |
| `BIGINT UNSIGNED` (tiền VND) | `BIGINT` + `CHECK (col >= 0)` | |
| `TIME` | `TIME` | checkin_time / checkout_time |
| `CHAR(3)` | `CHAR(3)` | currency |
| `ENGINE=InnoDB DEFAULT CHARSET...` | bỏ | PG mặc định |
| backticks | bỏ | |

## 3. Khác biệt hành vi cần lưu ý

1. **Sequence / identity:** seed insert ID tường minh → phải chạy `setval()` ở cuối
   `002_seed.sql` để đồng bộ sequence (nếu không, insert sau sẽ trùng ID).
2. **`day_of_week` (rate_rules):** giữ nguyên quy ước **1 = Chủ nhật … 7 = Thứ 7**
   (giống MySQL `DAYOFWEEK()`). PostgreSQL `EXTRACT(DOW FROM d)` trả 0–6 (0=CN),
   nên backend dùng `EXTRACT(DOW FROM d) + 1` để khớp quy ước lưu trữ.
3. **Time zone:** `TIMESTAMPTZ` lưu theo UTC nội bộ; demo seed dùng offset `+07`
   (Asia/Ho_Chi_Minh). Ứng dụng quyết định timezone hiển thị.
4. **Truncate + CASCADE:** seed dùng `TRUNCATE ... RESTART IDENTITY CASCADE` — chỉ
   đụng bảng trong schema YangHomestay.
5. **CHECK constraints:** PostgreSQL **bắt buộc thực thi** CHECK (khác MySQL 5.7 bỏ qua).
   Seed đã đảm bảo dữ liệu hợp lệ: `check_out > check_in`, rating 1–5, tiền ≥ 0…
6. **RLS:** đây là điểm mới so với MySQL — bật RLS toàn bộ (xem `004_rls.sql`).
   Backend dùng service_role key để bypass.

## 4. Seed — giữ nguyên dữ liệu

- Cùng số lượng: 5 properties, 16 units, 18 amenities, 19 tags, 7 rate rules,
  2 promotions, 12 bookings, 33 booking_nights, 5 reviews, 8 customers, 3 admins…
- Cùng ID tường minh → quan hệ FK giữ nguyên, dữ liệu coherent.
- Password bcrypt **giữ nguyên hash** (tương thích `password_hash()`/`password_verify()`).
- Khác biệt duy nhất: cú pháp BOOLEAN (`TRUE`/`FALSE`), `::jsonb`, timestamp `+07`.

## 5. Dữ liệu từ `hotel_management` → Supabase

Việc migrate dữ liệu thật từ `hotel_management` sang Supabase là công việc cần một kế hoạch chuyển đổi riêng
(theo `database/migration-notes.md` — bản đồ hotel_management → yang_homestay vẫn áp dụng
nguyên vẹn cho PostgreSQL). Các bước khuyến nghị:

1. Export từ MySQL (`mysqldump`) hoặc query qua PHP.
2. Transform theo bảng map (users→admins, rooms→units, bookings→bookings+nights…).
3. Import qua SQL Editor / REST API với service_role.
4. Verify đối chiếu tổng tiền, số đêm, trạng thái.
